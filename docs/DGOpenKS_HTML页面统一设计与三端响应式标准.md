# DGOpenKS HTML 页面统一设计与三端响应式标准

> 状态：正式标准
>
> 适用范围：`chapter_02-1`、`chapter_02-2`、`chapter_03`、`chapter_04`、`chapter_05` 的章节首页与知识页面，以及此后按本标准新建的页面
>
> 唯一性：本文件是页面结构、视觉系统、三端布局和完成验收的唯一规范来源。

## 1. 标准治理

本标准解决页面实现的一致性问题，不改写核心 Markdown 中的数学理解。

`chapter_00`、`chapter_01` 和站点首页属于既有独立页面，未完成迁移前不作为第三至第五章的实现参考；它们后续迁移时直接采用本标准，不新增兼容规则。

执行时必须遵守以下边界：

1. 根目录 `AGENTS.md` 负责知识内容、Markdown、HTML 派生、交互和数学准确性原则。
2. 本文件负责页面结构、公共组件、响应式行为和页面验收。
3. `00_初高中衔接知识/assets/learning-page-system.css` 是公共视觉规则的唯一实现。
4. 章节 CSS 只负责本章特有的数学图解、交互和必要的局部排版。
5. 其他文档不得复制本文件的断点、组件尺寸或完成标准；需要引用时只链接本文件。
6. 标准发生变化时，先修改本文件和公共 CSS，再修改具体页面。
7. Three.js、渲染器、依赖或模块加载方式的升级，默认不得改变页面视觉、组件样式或学习路径。如果同时需要视觉迁移，必须作为独立任务和独立差异进行验收。
8. 页面引用的公共 CSS、JavaScript、字体、图片和渲染资源必须进入 Git 索引。“本地文件存在”不等于“部署可用”；完成验收必须检查部署资源闭包。

出现冲突时，按照“数学与知识准确性优先于页面表现，公共标准优先于章节自定义”的顺序处理。

## 2. 页面实现前置条件

开始制作或重构 HTML 前，必须确认：

- 存在已认可的源 Markdown；
- 页面核心学习问题单一、明确；
- 移除图像和交互后，文字仍能解释知识；
- 已确定页面类型；
- 已完成 Markdown backflow 判断；
- 涉及大型图解或交互时，已完成 Interaction / Rendering Plan。

源 Markdown 不完整时，先报告缺失解释。未经授权，不得在 HTML 中补写新的核心数学解释。

## 3. 页面类型

每页只选择一个主要类型：

| 页面类型 | 主路径 |
| --- | --- |
| 概念博客页 | 问题 → 对象 → 特征 → 边界 → 示例与反例 → 结论 |
| 公式讲解页 | 原式 → 中间步骤 → 每步理由 → 公式结论 → 结构图解 → 应用检查 |
| 交互可视化页 | 预测 → 操作 → 状态变化 → 观察 → 解释 → 迁移 |
| 3D / 模型页 | 文字解释 → 静态结构图 → 模型观察 → 对应关系 → 结论 |

图解、公式和 3D 可以作为次要模块，但不得改变主要学习路径。

## 4. 统一页面骨架

知识页按需要从下列骨架中选取模块，顺序不得无理由打乱：

```text
顶部导航
→ 首屏学习契约
→ 连续核心解释
→ 推导 / 定义 / 方法步骤
→ 图解或结构对应
→ 解释性例子或结构判断
→ 核心结论
→ 前后页导航
```

强制要求：

- 首屏说明“学什么、解决什么困惑、理解会发生什么变化”；
- 首屏默认采用与“立方相关公式”一致的单栏结构：标签、标题和导语按阅读顺序纵向排列；
- 学习契约由标题与导语自然表达，不单独增加横线、圆点、提示条或“读完后你应该能”组件；
- 一级标题采用“知识对象：处理方向”结构时，冒号后必须显式换行；不能依赖视口宽度造成偶然折行；
- 公共样式不得提供强制两栏的 `lesson-hero`、右侧 `hero-stage` 或同类首屏舞台组件；
- 公式、结构图和学习路径图进入正文后，放在对应解释附近，不在首屏重复包装成装饰面板；
- 正文保持连续可读，不把主要解释拆散到标签页、折叠面板或轮播中；
- 每个公式步骤旁边有对应理由；
- 每个图解或交互前后都有观察提示和解释；
- 核心结论回到首屏提出的同一个问题。

### 4.1 纯知识内容边界

DGOpenKS 的核心 Markdown 与知识 HTML 只负责解释知识。固定例子、反例、结构比较和完整推导可以用于说明数学关系，但不得要求学习者提交答案。

Markdown、HTML、CSS 和 JavaScript 均不得包含练习、自测、作答、答案选择、正误反馈、重试、下一题、随机出题、题目生成器或练习树入口。解释性可视化交互可以保留，但只能帮助观察公式步骤、结构、边界或变化，不得转化为答题流程。

## 5. 公共设计变量

公共变量只在 `learning-page-system.css` 中定义。

### 5.1 宽度

| 变量 | 标准值 | 用途 |
| --- | ---: | --- |
| `--page-max` | `1180px` | 页面、导航和主内容最大宽度 |
| `--reading-max` | `920px` | 连续阅读内容最大宽度 |
| `--page-gutter` | `20px` | 电脑和平板基础边距 |
| 手机边距 | `14px–16px` | 小屏安全留白 |

章节不得重新定义这些变量。

### 5.2 颜色语义

| 颜色 | 语义 |
| --- | --- |
| blue | 原始对象、起点、主要学习路径 |
| amber | 第一类变化、待判断状态、混合项 |
| purple | 第二类变化、结构连接、对照 |
| cyan / green | 整理后的结果、正确状态、核心结论 |
| red | 删除、抵消、错误、禁止状态 |

颜色不能成为唯一的信息载体；必须同时提供文字、符号、边框或形状差异。

### 5.3 字体

- 正文使用无衬线中文字体栈；
- 一级、二级标题使用中文衬线字体栈；
- 数学表达式使用数学字体栈；
- 正文手机端不得小于 `16px`；
- 不得通过极端压缩字号、字距或行高强行容纳内容。

## 6. 三端响应式标准

页面只有一份 HTML。设备差异通过公共 CSS 重排，不创建独立的手机版或平板版页面。

### 6.1 设备范围

| 范围 | 设备级别 | 页面行为 |
| --- | --- | --- |
| `≥1024px` | 电脑 | 完整阅读布局；允许章节侧栏和安全的左右图文结构 |
| `821–1023px` | 横屏或宽平板 | 压缩侧栏；复杂公式说明、模型和大卡片优先上下排列 |
| `641–820px` | 竖屏平板 | 主内容单栏；章节标记移到正文上方；控件保持触控尺寸 |
| `≤640px` | 手机 | 完全单栏；紧凑标题与间距；表格、公式和图解使用专门小屏方案 |
| `≤360px` | 小手机补充 | 只允许微调字号和间距，不改变知识顺序 |

设备级别仍然只有电脑、平板、手机三类；`820px` 用来处理平板方向差异，`360px` 只处理极小手机。

### 6.2 允许的全局断点

公共页面布局只允许：

```css
@media (max-width: 1023px) { /* 平板 */ }
@media (max-width: 820px)  { /* 竖屏平板 */ }
@media (max-width: 640px)  { /* 手机 */ }
@media (max-width: 360px)  { /* 小手机补充 */ }
```

章节不得新增 `680px`、`760px`、`860px`、`900px`、`980px` 等旧全局断点。

只有数学图形确实在特定宽度发生结构破坏时，才可增加组件级断点，并必须：

1. 限定在该组件选择器；
2. 在 CSS 注释中写明破坏原因；
3. 不修改全局页面容器、标题、章节标记或导航；
4. 在三端验收记录中说明。

优先使用 Grid、Flex、`minmax()`、`clamp()` 和容器内自然换行，减少新增断点。

### 6.3 电脑端

- 主区域最大宽度为 `1180px`；
- 标准章节结构为 `150px` 标记栏加最高 `920px` 正文；
- 章节标记可吸附，但不得遮挡内容；
- 图文左右布局只有在两侧均可清晰阅读时使用；
- 首屏保持单栏，不为填充右侧空间增加路径卡片、公式卡片或带框舞台；
- 首屏不得被大型视觉组件完全占据。

### 6.4 平板端

- 宽平板允许使用缩窄标记栏；
- 竖屏平板将标记栏变为正文上方的横向标记；
- 两列卡片在内容变窄、公式换行或控件拥挤时改为单列；
- 复杂模型、图解和说明改为上下排列；
- 不得把电脑版按比例缩小；
- 所有可点击控件的可操作区域至少为 `44×44px`。

### 6.5 手机端

- 页面不得产生根节点横向滚动；
- 长公式优先分步重排；不可合理拆分时，只允许公式自身容器横向滚动；
- 数据表格使用横向滚动、行卡片转换或简化对照，不压缩成不可读小字；
- 标题自然换行，不使用人为补字或删改数学含义来配合版式；
- 导航可横向滚动，但必须保留焦点状态和触控尺寸；
- 图片、SVG、Canvas和3D不能超出视口；
- 图解标签不得覆盖数学对象；
- 核心操作不得依赖 hover。

## 7. 公共组件合同

公共 CSS 至少提供并统一以下组件：

- `.topbar`、`.topbar-inner`、`.brand`、`.nav-link`；
- `.hero`、`.eyebrow`、`.lead`；
- `main`、`.section`、`.section-body`、`.prose`、`.marker`；
- `.formula-card`、`.calc-steps`、`.calc-step`、`.formula-line`、`.step-note`；
- `.note`、`.summary-panel`；
- 通用焦点状态、减弱动画和打印规则。

`.hero` 是单栏首屏的唯一公共布局。公共 CSS 不提供 `.lesson-hero`、`.hero-stage`、`.hero-copy`、`.stage-label`、`.stage-expression`、`.stage-note` 或 `.learning-contract`。首屏学习目标必须写进标题和导语，不能另做带横线、圆点或提示色的视觉组件。

如果某个知识页确实需要在首屏出现可视对象，必须先证明它直接支持首屏提出的学习判断，并在页面局部实现；不得把它抽成所有章节默认继承的公共右侧舞台，也不得因此制造无内容的占位空间。通常应把公式、图解和路径放入正文对应段落。

章节可以新增组件，但不得复制上述组件的完整定义。

章节 CSS 可以：

- 定义本章专用结构图、数轴、符号表和模型；
- 为专用组件补充局部布局；
- 使用公共颜色和尺寸变量。

章节 CSS 不可以：

- 重新定义 `:root` 公共变量；
- 重写全局 `body`、`main`、`h1`、`h2`；
- 重新实现 `.topbar`、`.hero`、`.section`、`.marker`；
- 创建另一套卡片、阴影、圆角或断点系统；
- 使用大段页面内 `<style>` 重建公共布局。

## 8. 公式、图解和交互

### 8.1 公式

- 从原式开始；
- 显示必要的中间步骤；
- 每步说明变化和依据；
- 说明系数、符号、消去或分组来源；
- 最后到达结论；
- 图解只能在文字推导清楚之后帮助观察结构。

公式不得裁切、过小、错误换行或只以图片出现。

### 8.2 图解

- 数学位置、比例、标签和公式状态保持一致；
- 默认可见的静态图应尽量保留核心推理；
- 颜色之外还要有标签、边界或形状差异；
- 标签使用独立空间或引线，不覆盖关键对象。

### 8.3 交互

- 每个控件对应一个明确学习动作；
- 页面说明操作前要观察什么、操作后说明观察意味着什么；
- 提供键盘、触控和恢复初始状态的方式；
- 提供加载、失败和静态后备状态；
- 遵守 `prefers-reduced-motion`；
- WebGL、Canvas或动画失败时，核心解释仍然存在。

## 9. 三端验收矩阵

每个新建或重大修改页面必须实际检查：

| 名称 | 视口 |
| --- | --- |
| 电脑 | `1440×900` |
| 横屏平板 / 小电脑 | `1024×768` |
| 竖屏平板 | `768×1024` |
| 常规手机 | `390×844` |
| 小手机 | `360×800` |

每个视口检查：

- 首屏学习契约是否清楚；
- 阅读顺序是否一致；
- 是否存在页面级横向溢出；
- 公式、表格和图解是否可读；
- 标签和控件是否重叠；
- 触控区域是否足够；
- 交互状态及其解释是否完整可见；
- 本地资源、控制台和运行时是否报错。

提交或交付前，从仓库根目录运行：

```bash
python3 quality_checks/check_learning_page_standard.py
```

该检查从公共 CSS 自动读取允许的断点，并检查旧标准残留、公共样式接入、章节变量与公共页面选择器重定义、viewport、一级标题和样式路径。检查失败时不得声明页面完成。

## 10. 完成门槛

必须依次通过：

```text
源 Markdown 已确认
→ HTML Derivation Plan 已完成
→ 公共 CSS 已接入
→ 知识主路径完整
→ 三端实测通过
→ UI 质量复核通过
→ 重型渲染性能复核通过（如适用）
→ 才能声明完成
```

以下任一情况出现时，页面不得声明完成：

- 没有源 Markdown 或未说明 provisional 状态；
- HTML 发明了新的核心数学解释；
- 页面没有引用公共 CSS；
- 章节 CSS 重建公共布局；
- 使用未批准的全局断点；
- 平板没有单独检查；
- 页面级横向溢出；
- 公式或图解不可读；
- 核心内容依赖图像、交互或 hover；
- 没有三端检查证据；
- 只报告“应该可用”，没有实际打开验证。

## 12. 旧页面迁移

迁移顺序：

1. 接入公共 CSS；
2. 删除章节 CSS 中重复的公共变量和公共组件；
3. 将旧断点收敛到批准的断点；
4. 保留本章特有数学图解和交互；
5. 完成五个视口验收；
6. 删除旧公共样式文件和兼容层。

禁止长期保留两套公共样式、两份断点标准或“新旧规则并行”的兼容状态。
