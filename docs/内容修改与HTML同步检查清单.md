# DGOpenKS 内容修改与 HTML 同步检查清单

这份文档用于减少 Markdown 与 HTML 反复修正、表述不统一和页面排版返工。它同时记录 2026 年 7 月 21 日“立方相关公式”的修改结论，作为后续同类内容的参考。

## 1. 固定工作顺序

1. 先确定知识对象、核心问题和不展开的范围。
2. 先修改 Markdown，确认数学意义和表述。
3. 检查 Markdown 的推导、理由、条件、边界和检查方法。
4. Markdown 确认后，再同步修改 HTML。
5. 对照 Markdown 逐段检查 HTML，不在 HTML 中另外发明数学解释。
6. 检查桌面端与移动端的实际显示。
7. 最后检查文件差异、链接、标签闭合和格式。

核心原则：Markdown 是数学理解的来源，HTML 负责组织阅读路径和视觉层次。

## 2. Markdown 数学内容检查

### 2.1 公式推导

- 先写原式，再写中间步骤，最后得到结论。
- 每一个关键式子附近都要说明“这一步变了什么”和“为什么可以这样变”。
- 系数、正负号和混合项要说明来源，不只给出记忆结论。
- 几何、图像和交互放在代数推导之后，用来辅助看见结构。

### 2.2 不能省略的“理由桥梁”

出现下列跳转时，必须补上中间依据：

- 从“原式为 $0$”跳到“存在一次因子”；
- 从“几何切分”跳到“代数项的系数”；
- 从“设未知系数”跳到“系数的取值”；
- 从“观察到一个结果”跳到“这个结果总是成立”。

本次立方和、立方差的关键补充是因式定理：

$$
P(r)=0\quad\Longleftrightarrow\quad a-r\text{ 是 }P(a)\text{ 的因子}
$$

设原式为 $0$ 是为了寻找使多项式为 $0$ 的取值，再写出对应的一次因子。原多项式本身仍然保持不变。

### 2.3 方法的适用条件

每个方法都要回答：

- 它解决什么问题？
- 什么条件下可以使用？
- 什么时候有更直接的方法？
- 得到结果后怎样检查？

对多项式因式分解，先检查公因式。当目标是继续因式分解、原式可以看作某个字母的多项式，并且需要寻找一次因子时，可以尝试利用使原式为 $0$ 的取值。

## 3. 文字风格检查

- 使用学习者可以直接读懂的语言。
- 需要统一视角时，优先使用“我们”。
- 减少“不是……而是……”类的转折句，直接说明正面关系。
- 术语保持一致。本次统一使用“立体图形”，避免同一页中“立体”与“立体图形”混用。
- 数学结论句要补全句号。
- 不为了让两行字数相同而人为改写句子。
- 段落不使用首行缩进，以段间距区分段落。

## 4. Markdown 与 HTML 同步检查

每次同步时建立简单的对照关系：

| Markdown 内容 | HTML 位置 | 检查点 |
| --- | --- | --- |
| 开头对象与学习目标 | 主标题和副标题 | 首屏能否说清学什么 |
| 代数推导 | 公式步骤区 | 中间步骤和理由是否相邻 |
| 结构解释 | 对比区或图解区 | 是否只表达源文已有的理解 |
| 适用条件 | 条件说明或判断流程 | 是否说清什么时候使用 |
| 核心结论 | 页尾结论区 | 是否回到同一个核心问题 |

同步完成后，搜索 Markdown 中最近修改的关键短语，确认它们已出现在 HTML 的对应位置。

## 5. HTML 排版检查

- 同类正文使用统一的内容右边界。
- 让文字根据容器宽度自然换行，不使用 `text-wrap: balance` 强制平衡每行字数。
- 副标题过长时先精简文字，不通过压缩字号、字距或内容宽度硬塞进一行。
- 右侧文字解释保持统一宽度，不为了补齐行长而改变局部容器宽度。
- 长公式使用可滚动或可换行的容器，避免手机端溢出。
- 不用图像、卡片或交互替代必要的数学文字。
- 有动效时提供 `prefers-reduced-motion` 处理。

## 6. 本次“立方相关公式”修改总结

### 差的立方

- 缩短副标题，保留“乘法推导 + 体积切分”两条路径。
- 明确几何模型需要 $a>b>0$，代数恒等式不受这个边长条件限制。
- 重写体积切割说明：减去三片 $a^2b$，加回三块 $ab^2$，再减去多算的 $b^3$。
- 统一几何区段的内容宽度和自然换行。

### 立方和与立方差

- 先从当原式 $=0$ 时寻找一次因子，再设二次因子的未知系数。
- 保留“原式没有 $a^2b$ 和 $ab^2$”的解释，再说明要让两类混合项消失，系数必须为 $0$。
- 几何解释改为正面表述，统一使用“我们”和“立体图形”。
- 右侧说明文字使用统一宽度，不追求两行字数一致。

### 立方公式小结

- 先区分“整体的立方”与“两个立方的和或差”。
- 明确前者用于展开，后者用于因式分解。
- 补充因式定理，说清利用 $0$ 寻找一次因子的理由、条件和边界。
- 将四个公式集中比较，并整理成可执行的结构判断流程。

## 8. 建议的长期做法

1. 每个章节开始修改前，先记录一份当前章节的“措辞和排版约定”。
2. 每次先一次性审核 Markdown 的数学链条，再进入 HTML，减少两个文件来回同步。
3. 将“理由桥梁、适用条件、检查方法”设为数学内容的强制审核项。
4. 使用自动检查发现链接、标签、公式和格式问题；数学解释和语言风格仍使用本清单人工复核。
5. 只有完成桌面端和移动端实际预览后，才将页面标记为完成。
